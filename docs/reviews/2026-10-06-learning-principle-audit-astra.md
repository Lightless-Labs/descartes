# Learn-and-adapt principle audit of past work — gpt-6-astra (xhigh)

**Date:** 2026-10-06
**Scope:** main @16d0ed9, capacity worktree, root-helper worktree. Read-only.
**Principle:** Descartes learns and adapts (data, context awareness, ability to learn); no expert-system rule forest; long memory; safety invariants are legitimate.

---

**Verdict: Descartes currently learns observed values and membership sets, but most decisions about what matters remain hand-written.** The strongest implementation work protects evidence integrity. The largest architectural gap is the missing loop from contextual observations and independently verified outcomes to revised, evaluated behavioral models.

A deterministic evaluator is compatible with the principle. A fixed hypothesis about normal behavior, indefinitely maintained through special cases, is the problem.

This was read-only. I inspected main (`16d0ed9`), the capacity worktree—including its concurrent freshness changes through `5928ca7`—and root-helper hardening (`24bf964`). I also ran two pure, in-memory checks; no files were written.

References below use main unless marked **Capacity** or **Hardening**. Classification:

- **A:** behavioral assumption requiring learning or observed context.
- **B:** legitimate evidence/safety invariant or resource bound.
- **C:** bootstrap prior, acceptable only with an implemented way to learn beyond it.
- **D:** delivery/UX policy.

**Structural verdict and highest-leverage changes**

The live architecture has four different maturity levels:

| Capability | Assessment |
|---|---|
| Grounded observation and refusal to fabricate | Substantial implementation, with explicit coverage limitations. Same-UID state remains an acknowledged trust limit. |
| Learning statistics and observed membership | Real, but narrow: rolling means/variance, seen sets, identity persistence, two constraint templates. |
| Learning normality conditional on machine context | Mostly absent. Peer collector-availability stratification is the clearest implemented starting point. |
| Revising models from validated outcomes | Largely absent from the running system. Manual constraint lifecycle exists; calibration is weak and repeated-event counting breaks its tuning trigger. Compositional model execution/promotion exists offline. |

The gap is therefore **architectural integration and data semantics**, not a shortage of additional detector rules. Five changes offer the most leverage:

1. **Build durable context observations and join them to measurements.** Start with lifecycle, network transitions, session origin and workload/update events. Record event time, observation time, scope and coverage. A reboot should supply explanatory evidence; it should not activate a blanket suppression timer.

2. **Separate bounded raw retention from long learning memory.** Complete per-family storage and seen-set integration, retain the requested long window, and add compact context-conditioned summaries plus event/incident sequences. Preserve older reference models alongside recent models so slow drift remains measurable. Every summary must retain its provenance and coverage interval.

3. **Make built-in behavioral detectors versioned, context-conditioned model artifacts.** Fit distributions and decision calibration from observed strata with uncertainty and sparse-data fallback. Bootstrap constants need explicit replacement criteria. Novelty should remain an accurate observation; learned/contextual assessment should determine significance. Keep arithmetic, schema, freshness and integrity checks outside model authority.

4. **Repair the outcome loop before claiming adaptive tuning.** Add append-only alert transitions and evidence-backed correction/incident records. Separate notification preference from detection correctness. Replace extrema-plus-margin and zero-fire promotion with held-out benign variation, known incident cases, slow-attack replays and measured false-positive/false-negative tradeoffs. Preserve authorization and audit controls.

5. **Connect the model runtime to a bounded shadow-learning cycle.** Observe → propose model version → replay → shadow → evaluate → promote within authorized policy → monitor → revoke/version. Keep uncertain or potentially hostile changes quarantined from automatic acceptance; compare against longer-term references. The existing IR/ladder is a starting component, not yet that cycle.

**The safety work should survive this correction intact. The behavioral assumptions should become revisable hypotheses, supported by context and evaluated outcomes.**
